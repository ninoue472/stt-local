# T-028: マイク権限を起動時に先行取得＋波形ベースライン即時表示（初回起動時に波形が出ない不具合）

## 目的
- 初回起動時、録音を開始しても「音声入力の状態を表す波形」が表示されない不具合を直す。
- 2回目以降は表示されることから、原因は **マイク権限の取得タイミングが録音開始時** で、
  初回セッションだけ「権限ダイアログ待ち＋権限確定直後の audioProcessor 起動」が競合し、
  最初のキャプチャがエネルギーを流さない（＝波形が動かない）こと。
- あわせて、`.recording` に入った瞬間から波形ベースラインを見せ、「マイクが生きている」ことを即伝える。

## 現状の問題箇所
- `AppDelegate.startRecording()` が `appState.bufferEnergy = []`（波形を消す）→ `phase=.recording`
  → `await st.start()` の順。波形ベースライン `[0]` は `start()` 内の **await（権限取得含む）後** に設定される
  （`StreamingTranscriber.swift:71-73`）。
- `StreamingTranscriber.start()` が `await AudioProcessor.requestRecordPermission()` を **録音開始時** に呼ぶ
  （`StreamingTranscriber.swift:60`）。初回はここでダイアログ。許可直後に `startRecordingLive` を叩く。
- 波形表示条件は `phase ∈ {.recording,.processing}` かつ `bufferEnergy` 非空（`PanelRootView.swift:92-100`）。

## 受け入れ条件
- [ ] マイク権限の要求を **アプリ起動時（モデルロードのプリウォーム段階）** に1回行う。
      未許可の初回はこの時点でダイアログが出て、ユーザー許可後に録音すれば最初から波形が動く。
- [ ] 既に許可済みの場合は副作用なし（再ダイアログ・遅延を生まない）。
- [ ] 権限が拒否されている場合の既存の挙動（`startRecording` 時のエラー表示）は維持する
      （起動時の先行要求は「失敗してもアプリは起動継続」、録音時に従来通りエラー文言を出す）。
- [ ] `.recording` に遷移した瞬間から波形ベースライン（`bufferEnergy=[0]` 相当）が表示される
      （`await` の前に同期設定し、ダイアログ待ちでも波形枠が出る）。`start()` 側の `[0]` 設定と二重でも害がないこと。
- [ ] 録音停止→再録音、モデル再ロード後の録音でも回帰がない。
- [ ] ビルド pass（`env -u CC -u CXX xcodebuild ...`）。

## 影響範囲（触ってよい範囲）
- `STTLocalApp/App/AppDelegate.swift`（権限の先行要求・`startRecording` のベースライン設定）
- `STTLocalApp/Speech/StreamingTranscriber.swift`（`start()` の権限チェック/ベースライン設定の整理）
- 必要なら `STTLocalApp/State/AppState.swift` への小さな補助のみ（UI ロジックの大改変は不可）

## 制約・前提
- WhisperKit の `AudioProcessor.requestRecordPermission()`（static async）を利用する。重複呼び出しは可。
- 波形は「入力モニタ」。文字起こしループや推論の重さに依存させない既存設計（タップコールバック駆動）を壊さない。
- T-029（ウォームアップ）と同一ブランチで実装される。プリウォーム処理に権限要求を相乗りさせてよい。
- ロジックは最小変更。UI レイアウトや配色は変更しない。
