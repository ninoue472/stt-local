# T-013: 波形固まり修正（推論を MainActor から外す）＋ 感度調整

## 目的
- 推論中も波形が滑らかに動き続け、「マイクが拾えている」ことを常に伝える。
- 根本原因は `StreamingTranscriber` が `@MainActor` で、`transcribe()` 中に MainActor が
  専有され波形更新 Task が滞ること。MainActor を空ける。

## 受け入れ条件
- [ ] `transcribe()` 実行中も波形が更新され続け、1 秒以上固まらない（手動確認）。
- [ ] 無音→静まる / 発話→立つ が入力に追従。通常会話の音量で領域高さの大半まで立つ。
- [ ] **回帰なし**: 同一音声で `stop()` の最終テキストが変更前と一致。
- [ ] `[STT/timings]` の pipeline 時間が悪化しない（変更前後で比較）。

## 影響範囲
- `STTLocalApp/Speech/StreamingTranscriber.swift`（並行性の変更）
- `STTLocalApp/UI/WaveformView.swift`（`normalizedEnergy` の感度調整のみ）

## 制約・前提
- **タイミング中立を厳守**: 音声窓・`clipTimestamps`・スライド/purge・`minNewAudioSeconds` は不変。
  バッファ操作は「現在のライブ長」基準を維持（`docs/plan/vad-regression-fix.md`）。
- `appState`（@MainActor）への書き込みは `await MainActor.run` で hop。エネルギー反映は MainActor 直行のまま。
- **高リスク領域**: 並行性変更は過去 T-001/T-004 でリバート済み。T-011/T-012 と分離コミットし、
  単独リバート可能にすること。`docs/knowledge/avoid-mutating-audio-pipeline-timing.md` 厳守。
- 感度ゲイン/指数は実機 `relativeEnergy`（無音/通常/大声）実測で決定。クリップ張り付き回避。
- 設計: `docs/plan/inference-status-and-waveform.md` の T-013 節。

## 完了の定義
- [ ] ビルドが通る
- [ ] 手動確認: 推論中も波形が動く＋感度十分＋入力追従
- [ ] 回帰確認: 最終テキスト一致 / timings 悪化なし
- [ ] spec/plan と齟齬なし
