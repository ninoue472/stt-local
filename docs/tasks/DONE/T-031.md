# T-031: 空テキスト時のクリップボード上書き＆誤トーストを止める

## 目的
- 録音停止時、最終テキストが空でも無条件にクリップボードを上書きし「コピーしました」トーストを出す
  バグを直す。無音・極短音声・全セグメントが幻聴除去された場合に `stop()` が空文字を返すと、
  ユーザーが直前にコピーしていた内容が**消える**（データ損失）うえ、何もコピーしていないのに
  成功と誤認させる。
- 2026-06-10 コードレビューで唯一「ユーザーの既存データを実際に破壊し成功と誤認させる」正しさ＋
  データ損失バグとして Top1 に選定（`docs/reviews/code-review-2026-06-10.md`）。

## 現状の問題箇所
- `AppDelegate.stopRecording()`（`AppDelegate.swift:130-139`）が `finalText` の内容に関係なく
  `Clipboard.copy(finalText)` と `flashCopiedToast()` を無条件に呼ぶ。
- `Clipboard.copy()`（`Clipboard.swift:4-8`）は `clearContents()` 後に `setString` するため、
  空文字を渡すと既存クリップボード内容が消える。

## 受け入れ条件
- [ ] `finalText` が trim 後に空のとき、`Clipboard.copy` が呼ばれず既存クリップボード内容が保持される。
- [ ] `finalText` が trim 後に空のとき、`flashCopiedToast`（「コピーしました」）が表示されない。
- [ ] `finalText` が非空のときは従来通りコピー＆トーストが行われる（回帰なし）。
- [ ] `lastFinalText` を空で上書きしてよいか判断し、空での上書きが UI（再表示/再コピー導線）に
      悪影響を与えないこと。
- [ ] 空入力ケースのユニットテストを追加（`STTLocalAppTests`）。空 `finalText` でコピー・トーストが
      発火しないことを検証する。
- [ ] ビルド pass（`env -u CC -u CXX xcodebuild ...`）。

## 影響範囲（触ってよい範囲）
- `STTLocalApp/App/AppDelegate.swift`（`stopRecording` の空判定ガード）
- `STTLocalApp/Speech/Clipboard.swift`（必要なら空文字ガードを `copy` 側に持たせるか検討）
- `STTLocalAppTests/`（テスト追加）

## 制約・前提
- 修正は局所的・低リスクに留める（空判定の早期 return）。UI レイアウト・配色は変更しない。
- 「空判定をどこに置くか」は `stopRecording` 側を基本とし、`Clipboard.copy` 側に置く場合も
  呼び出し側のトースト発火と整合させること（コピーしていないのにトーストが出ない）。
- trim は既存の `copyableText`/`assembledText` の trim 方針と一致させる。
