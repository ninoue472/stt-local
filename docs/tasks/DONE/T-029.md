# T-029: モデルロード後にウォームアップ推論を1回実行（初回発話のコールドスタート遅延を解消）

## 目的
- 「初回起動時に特にラグ」の体感を減らす。原因は、モデルロード後に **実音声を流す初回 `transcribe()` だけ
  突出して重い**こと（プレフィル経路・各種バッファが未初期化のコールドパス）。
- `WhisperKitConfig.prewarm = true` はモデルのロード/コンパイルまでで、実推論ホットパスは温まらない。
- ロード完了直後に **ダミー音声で transcribe を1回**走らせ、初回の実推論を温めておく。

## 受け入れ条件
- [ ] モデルロード成功後・録音可能（`phase=.ready`）になる前に、ウォームアップ推論を **1回**実行する。
- [ ] ウォームアップ入力は **無音（または極短い）ダミー音声配列**で、ストリーミングと同じ `DecodingPresets.streaming`
      系オプション（言語は現在の `Settings.shared.language`）で1回 transcribe する。
- [ ] ウォームアップ結果は **破棄**し、`AppState`（confirmed/unconfirmed/bufferEnergy 等）に一切影響しない。
- [ ] ウォームアップ中の UI は従来の「読込中」表示のままでよい（完了後に `.ready`）。失敗しても
      アプリ起動は継続し、`.ready` に進む（ウォームアップ失敗で録音不能にしない）。
- [ ] モデル切替（reloadModel）後にも同様にウォームアップが走る。
- [ ] 効果確認の目安: 録音開始後 **初回ステップの `[STT/timings]` pipeline が定常値（~600〜930ms）に近い**
      こと（人間が `/tmp/stt.log` で確認できる形）。明確な数値受け入れは実機計測で判定。
- [ ] ビルド pass。

## 影響範囲（触ってよい範囲）
- `STTLocalApp/Speech/WhisperEngine.swift`（ウォームアップ用メソッドの追加が自然）
- `STTLocalApp/App/AppDelegate.swift`（`prewarmWhisper` からウォームアップを呼ぶ）
- 必要なら `STTLocalApp/Speech/DecodingPresets.swift` を参照（変更は不要のはず）

## 制約・前提
- ウォームアップは録音とは独立。`pipe.audioProcessor` の録音状態に触れない（`startRecordingLive` を使わない）。
  `pipe.transcribe(audioArray:decodeOptions:)` に自前のダミー配列を渡す方式にする。
- ダミー音声長は短く（例: 1.0秒・無音）。ロード時間を不必要に伸ばさない。
- T-028 と同一ブランチ。`prewarmWhisper` のフロー（cached 判定→load→`.ready`）を壊さない。
