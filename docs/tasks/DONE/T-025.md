# T-025: 窓のハードキャップ（確定待ちに依存しない強制スライド）で decode 膨張を抑える

## 背景（実測で判明した真因）
M5 Pro 実機の `[STT/timings]` ベースライン計測（budget=2.0s, モデル large-v3-turbo, ANE）:

| audioIn（窓長） | logmel | encode | decode | pipeline |
|------|------|------|------|------|
| 2.1s | 26ms | 314ms | 487ms | 508ms |
| 11.0s | 8ms | **279ms** | **1873ms** | **1902ms** |
| 4.1s | 8ms | 279ms | 1031ms | 1061ms |

- `encode` は窓長に依らずほぼ一定 **~280ms**（Whisper が常に 30s パディングで encode する固定費）。
  → 計算ユニット変更（旧 T-019 GPU 併用）は **却下**。支配項ではない。
- `decode` が **窓長に比例**して膨張し pipeline のほぼ全部を占める。
- 連続発話（息継ぎ少）で窓が **5.0s 上限を超えて 11s まで肥大**し、pipeline が budget(2000ms) を
  使い切る寸前まで悪化した。これが体感遅延の主因。

### 肥大の機序（要実装時確認）
`slideWindowIfNeeded` のスライド発火条件が
`bufferSeconds > maxWindowSeconds && lastConfirmedSegmentEndSeconds > overlapSeconds`
で、**確定境界に依存**している。連続発話で確定が遅れると窓がスライドせず育つ。さらに decode が
遅いほど transcribe 実行中に新規音声が溜まり窓が育つフィードバックで pipeline が budget へ接近する。

## 目的
- 連続発話でも推論窓を一定長に保ち、`decode`/`pipeline` を恒常的に小さく（目標 < 700ms）抑える。
- これにより遅延スパイクを根絶し、後続で `minNewAudioSeconds` を安全に短縮できる前提を作る。

## 受け入れ条件
- [ ] `[STT/timings]` に `confirmedEnd`（lastConfirmedSegmentEndSeconds）と `slid`（当該ステップで
      スライド発火したか）を追加し、連続発話で窓が肥大する機序を実測で確認・記録する（タイミング中立）。
- [ ] 推論窓に **ハードキャップ** を導入：`bufferSeconds` が上限（既定: maxWindowSeconds=5.0s、
      必要なら別途 `hardCapSeconds`）を超えたら、確定境界が無くても **強制スライド** する経路を追加。
- [ ] 強制スライド時、できるだけ **セグメント終端でカット**（語の途中で切らない）。カット前の
      セグメントのテキストは `committedText` へ確定（force-commit）し、表示・コピー内容を失わない。
- [ ] 連続発話（息継ぎなし 30s 以上）で `audioIn`（窓長）が上限+α（例 6〜7s）を超えない。
- [ ] 連続発話でも `pipeline` が恒常的に **< 1000ms（目標 < 700ms）**。
- [ ] 同一音声での最終テキストに脱落・重複・顕著な精度劣化がない（変更前後で比較）。
- [ ] 無音幻聴（定型句）が増えていない。

## 影響範囲
- `STTLocalApp/Speech/StreamingTranscriber.swift` のみ（`slideWindowIfNeeded`、診断ログ、必要なら定数追加）。

## 制約・前提
- **過去 T-001/T-004 のリグレッション領域**。`docs/knowledge/avoid-mutating-audio-pipeline-timing.md` 厳守。
  1レバーずつ・**単独リバート可能なコミット**で。
- バッファ purge は必ず「**現在のライブ長**」基準で計算する（transcribe 中に増えた新規音声を
  前から削らない）。`docs/plan/vad-regression-fix.md` 厳守。
- 強制スライドは未確定テキストを早期確定するため、末尾補正の機会をわずかに失い精度を犠牲にしうる。
  → **窓肥大による全体遅延より許容**する方針（要：人間の最終承認 / 下記「決定事項」参照）。
- 計測駆動：変更前後で同一手順（息継ぎなし連続発話 30s）の `[STT/timings]` を比較する。
  計測方法: `script -q /tmp/stt.log <app binary>`（PTY 経由でバッファ問題を回避）。

## 決定事項（確定済み・2026-06-05 人間承認）
- **方針: レイテンシ優先**。窓を確実に小さく保つ。
- ハードキャップ値: 既存の `maxWindowSeconds = 5.0s` を流用（別定数は追加しない）。
  強制スライド後は直近 ~`maxWindowSeconds` に収め、`audioIn`（窓長）が 6〜7s を超えないこと。
- **強制 force-commit を許容**（未確定末尾の早期確定によるわずかな精度犠牲は受容）。
- 目標 `pipeline` < 700ms（連続発話でも）。
