# T-027: 適応型budget（再推論間隔を実測pipelineで自動調整）

## 目的
- `minNewAudioSeconds`（再推論間隔=budget）を固定2.0sから、**直近pipelineのEMAで自動調整**へ。
- 速いチップ/軽いモデルでは budget が下がり体感がキビキビ、遅い条件では budget が上がり
  バックログ破綻を防いで安定。1コードで全チップ/全モデルに適応。Issue #7。

## 重要な性質
- budget はライブ更新の粒度を変えるだけで、**最終テキスト精度には影響しない**（正しさのリスク低）。
- T-025(窓キャップ)により decode スパンが頭打ちなので、制御ループは収束（暴走しない）。
- 「安定させる」機能であって「速くする」機能ではない（速くするのは軽量モデルの役割）。

## 受け入れ条件
- [ ] `minNewAudioSeconds` を `let`→`var` にし、毎 transcribe 後に実測 pipeline の EMA から再計算する。
- [ ] 計算式（おおむね）:
      - EMA は非対称: pipeline 増加時 alphaUp=0.5（素早く追従しバックログ防止）、
        減少時 alphaDown=0.2（過敏な短縮を避ける）。初回は実測値で初期化。
      - `budget = clamp(pipelineEMA × 1.2, 下限0.8s, 上限4.0s)`。
- [ ] 速いチップ(M5 Pro)で軽い局面は budget が下限付近へ下がり、ライブ更新が体感で速くなる。
- [ ] 重い局面（密発話）では budget が上がり、`pipeline < budget` を維持（バックログが溜まらない）。
- [ ] 最終テキストに脱落・重複・精度劣化なし。無音幻聴増なし。
- [ ] `[STT/timings]` の `budget=` が動的に変化して見える（既存ログがそのまま可視化に使える）。

## 影響範囲（触ってよいファイル）
- `STTLocalApp/Speech/StreamingTranscriber.swift` のみ。

## 実装メモ
- 状態/定数を追加:
  - `private var minNewAudioSeconds: Float = 2.0`（初期値=従来。以後は適応で上書き）
  - `private var pipelineEMASeconds: Float = 0`（0=未初期化）
  - 定数: `budgetFloor=0.8`, `budgetCap=4.0`, `budgetSafetyFactor=1.2`, `emaAlphaUp=0.5`, `emaAlphaDown=0.2`
- 更新箇所: `transcribeStep` 内、transcribe 完了後。**診断ログ(`[STT/timings]`)の if ブロックとは別に**
  独立した更新ブロックを置く（診断ログは将来削除予定(Issue #6)なので依存させない）:
  ```swift
  if let t = results.first?.timings {
      let pipelineSec = Float(t.fullPipeline)
      if pipelineEMASeconds == 0 {
          pipelineEMASeconds = pipelineSec
      } else {
          let a = pipelineSec > pipelineEMASeconds ? emaAlphaUp : emaAlphaDown
          pipelineEMASeconds = a * pipelineSec + (1 - a) * pipelineEMASeconds
      }
      minNewAudioSeconds = min(max(pipelineEMASeconds * budgetSafetyFactor, budgetFloor), budgetCap)
  }
  ```
- guard（`nextBufferSeconds > minNewAudioSeconds`）はそのまま。budget が var になるだけ。
- バッファ/スライド(T-025無損失版)・updateSegments には触らない。
