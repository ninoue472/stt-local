# レビュー: T-026 モデル選択UI ＋ 量子化既定（軽量化/M1対応）

対象: `STTLocalAppApp.swift`, `AppDelegate.swift`, `AppState.swift`, `Settings.swift`,
新規 `ModelCatalog.swift`, `PanelRootView.swift`, `README.md`
ブランチ: `feat/model-selection`（base: main）

## 実装
- **ModelCatalog**: 3モデルを型定義（高精度 `large-v3_turbo`/約3GB、標準(推奨)
  `large-v3_turbo_954MB`/約954MB、軽量 `small_216MB`/約216MB）。
- **既定モデル**を量子化版 `openai_whisper-large-v3_turbo_954MB` へ。
- **メニューバー**＋**パネル**の両方にモデル選択ドロップダウン（言語と同一UI）。現在モデルに✓、
  サイズ表示、`.ready/.error` 時のみ変更可。選択ロジックは `AppState.selectModel` に共通化。
- **再ロード**: 選択→`Settings.modelName` 更新＋`.reloadModel` 通知→`AppDelegate` が
  `.ready/.error` 時のみ `prewarmWhisper()` 再実行（旧 engine/transcriber を解放してから新規ロード）。
- `StreamingTranscriber`（perf T-025）は未変更。`isModelReady` のデッドコードは除去。

## ビルド / レビュー
- クリーン/通常ビルドとも **BUILD SUCCEEDED**。新規ファイルは pbxproj 登録済み。
- 良い点: カタログ外モデル時はラベルに生モデル名フォールバック（`defaults` 直設定にも耐える）。
  録音中ガード、永続化（既存 Settings）、メモリ解放（旧 engine 破棄）も適切。

## 実機計測（M5 Pro・同一発話で高精度 vs 標準量子化）
| 観点 | 高精度 (3GB) | 標準・量子化 (954MB) |
|---|---|---|
| 固有名詞 | 「井上**則人**」漢字変換◎ | 「井上**のりひと**」ひらがな止まり |
| 本文 | 全文・正確 | 全文・ほぼ同等（末尾に微小ゴミ） |
| テキスト消失 | なし | なし |
| encode | ~280-320ms | ~256-285ms |
| decode | 634-1620ms | 611-1748ms |
| pipeline | 675-1639ms | 631-1767ms |

### 知見
- **量子化版は実用上ほぼ同等**だが、固有名詞の漢字変換がやや弱い（人名など）。
- **M5 Pro では量子化版は速くならない**（encode/decode はほぼ同等）。量子化の利点は
  **メモリ/サイズ（954MB vs 3GB）**で、効くのは M1 等の下位機。
- 切替・再ロード・✓表示・録音中ガードはメニューバー/パネル両方で機能。

## 決定
- **既定 = 標準・量子化(954MB)** のまま（人間判断 2026-06-08）。配布・M1 互換を見据える。
  高精度が要る場合はセレクタで切替（M5 Pro では速度・メモリ不利なし）。
- 結論: **承認**。
