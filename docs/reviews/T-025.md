# レビュー: T-025 窓のハードキャップ（強制スライド）

対象: `STTLocalApp/Speech/StreamingTranscriber.swift`
ブランチ: `feat/perf-window-cap`

## 第1ラウンド（Codex 初版）
- ビルド: Claude 側で `env -u CC -u CXX xcodebuild ... CODE_SIGNING_ALLOWED=NO` → **BUILD SUCCEEDED**。
- 良い点:
  - `slideWindowIfNeeded` が `Bool` を返し `[STT/timings]` に `confirmedEnd`/`slid` を追加（診断強化・タイミング中立）。
  - purge は両経路とも `pipe.audioProcessor.audioSamples.count` のライブ長基準を維持（vad-regression-fix 準拠）。
  - force-commit でカット前テキストを `committedText` に退避（表示・コピー内容を保持）。
- **指摘（要修正）**: 確定境界ブランチ（`lastConfirmedSegmentEndSeconds > overlapSeconds`）が窓長を保証しない。
  `cut = confirmedEnd - overlap` のみ切るため、確定が少ししか進んでいない連続発話で窓が
  `maxWindowSeconds` を大きく超えたまま残る（例: buffer=11s, confirmedEnd=2s → cut=1s, 窓10s 残存）。
  ハードキャップが `confirmedEnd <= overlap` 限定で発火するため、本来狙った「連続発話で窓が育つ」
  ケースを取りこぼす。
  → 修正方針: 両ブランチ統合し、`slid==true` 後の残窓を必ず `maxWindowSeconds` 以下に
  （最低 `requiredCut = bufferSeconds - maxWindowSeconds` を切る）。`confirmedCut >= requiredCut` なら
  既存のクリーンな確定境界スライド、そうでなければ requiredCut 以上の最も手前のセグメント終端で強制スライド。

## 第2ラウンド（窓長保証の修正後）
- ビルド OK。窓長は常に maxWindowSeconds 以下に bound されるよう統合（confirmedCut>=requiredCut 判定）。
- **実機計測（連続発話30s）でレイテンシは劇的改善**: pipeline 340〜600ms 中心、窓 6〜7s で頭打ち
  （ベースライン 1902ms/11s）。ハードキャップ自体は機能。
- **しかし重大リグレッション2件を検出 → 第3ラウンドへ差し戻し**:
  1. **テキスト消失**: `confirmedEnd=0.0s slid=true` が大半＝ほぼ毎回 force-commit ブランチを通る。
     セグメント境界に合わない位置で音声をカットしつつテキストを確定しきれず、連続発話（窓が1長セグメント）で
     発話が丸ごと欠落。vad-regression-fix.md の「発話スキップ」を再発させた。
  2. `audioIn=40.4s` の異常値: force-commit + `lastConfirmedSegmentEndSeconds=0` リセットによる
     バッファ座標 desync の痕跡。

## 第3ラウンド（force-commit 全廃・安全版）
- 方針: 未確定テキストの force-commit を廃止。窓を縮める必要があるときは**先頭セグメントを丸ごと
  confirmed へ昇格**させてから、**実績ある確定境界スライド**（overlap 保持・overlap から再デコード・
  セグメント単位で無損失）を使う。途中カット・0リセットを一切しない。

## 受け入れ計測（実機・連続発話30s）
- ベースライン: 窓 11s / decode 1873ms / pipeline 1902ms（budget 2.0s）。
- 目標: `audioIn` ≤ 6〜7s 維持、`pipeline` < 1000ms（目標 <700ms）、**テキスト消失ゼロ**、幻聴増なし。
- 第2ラウンド結果: レイテンシ目標達成も**テキスト消失で不合格**。
- 第3ラウンド結果（クリーンビルドで安全版を確実に計測）:
  - レイテンシ良好（pipeline 大半 340〜700ms、密発話で最大~1330ms、窓 5〜7s）。confirmedEnd も正常(1.0/2.0/3.5)。
  - 旧版の 40.4s force-commit 異常は消滅。無音時に窓が伸びる(10.5s/25.5s)が decode 軽く無害。
  - **ただしテキストが『一部』消失**（前回の全消失からは改善）。原因＝force-confirm が最後の
    不安定セグメントまで確定し、Whisper のタイムスタンプ不正確さで継ぎ目の単語が落ちる
    （ストリーミングASRの継ぎ目問題）。

## 第4ラウンド（継ぎ目消失の根治）
- 設計判断（人間承認: 継ぎ目を正しく直す）: char 単位 de-dup は日本語で不安定なため非採用。
  代わりに**元の無損失原理『後続セグメントがある安定境界だけ確定（最後の1つは必ず未確定で残す）』を
  force-confirm にも適用**。while 条件に `unconfirmedSegments.count > 1` を追加し最後の1セグメントを
  昇格させない。確定境界がすべて安定化し、継ぎ目の単語落ちが原理的に消える。
  極端な単一巨大セグメント時のみ確定が進まず窓が育つ（遅くなるが無損失・許容）。
