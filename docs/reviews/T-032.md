# レビュー: T-032 prewarmWhisper の多重実行を直列化

- 対象 PR: #14（予定）
- 実装: Codex / レビュー: Claude
- 起点: `docs/reviews/code-review-2026-06-10.md`（Top2）

## 実装の要点

`prewarmWhisper()` を2層に分離（`AppDelegate.swift`）:

1. **要求登録 + 直列実行ループ** (`prewarmWhisper`)
   - `latestPrewarmGeneration += 1` で世代を採番し `requestedGeneration` を捕捉。
   - `guard !isPrewarmRunning else { return }`：実行中なら世代だけ上げて即 return（@MainActor のため
     check-and-set はアトミック）。
   - 実行中でなければ `isPrewarmRunning = true`（`defer` で解除）し、while ループで
     `runPrewarmWhisper(generation:)` を回す。完走後 `generationToRun != latestPrewarmGeneration` なら
     最新世代で再実行 → **常に最新要求が最後に走る**。
2. **実体ロード** (`runPrewarmWhisper(generation:)`)
   - 各 await 境界（`isModelCached` / `load` / `warmupTranscription` / transcriber 生成）で
     `guard generation == latestPrewarmGeneration else { return }`。陳腐化した実行は副作用反映前に脱出。
   - `load` の progress クロージャ内でも世代ガード（古い progress で phase を書き戻さない）。
   - 最終反映は `engine`/`transcriber`/`.ready`/`.error` を全て世代ガード下で行い、`whisperEngine` と
     `streamingTranscriber` をまとめて差し替え。

## 受け入れ条件の検証

| 受け入れ条件 | 結果 | 根拠 |
|---|---|---|
| 連続発火でも同時に走る prewarmWhisper は常に1つ | ✅ | `isPrewarmRunning` ガード + while ループ。実行中の追加要求は世代更新のみで return |
| 世代トークンで最新世代の結果のみ反映 | ✅ | `latestPrewarmGeneration` と各 await 後の `guard`。旧世代は phase/engine/transcriber を反映せず脱出 |
| currentModelName と実 engine が一致 | ✅ | `.ready` 到達時、最新世代が `currentModelName`（開始時）と `whisperEngine`（完了時）を同一 modelName で設定。ロード中は `.loadingModel/.downloadingModel` で録音不可のため不整合が露出しない |
| CPU/メモリの二重消費が起きない | ✅ | 直列化で重複ロード/warmup が走らない。陳腐化実行は早期脱出 |
| 再試行連打・モデル連続切替で不整合が残らない | ✅(コード上) | 設計上担保。最終的な実機での連打確認は人間承認時に推奨 |
| ビルド pass | ✅ | `xcodebuild ... test` → **13 tests, 0 failures / TEST SUCCEEDED**（Claude 環境で代行検証） |

## 設計評価

- **良い点**: re-entrancy 防止（フラグ）と「最新だけ反映」（世代トークン）を分担させた素直な構成。
  陳腐化実行の早期脱出で CPU 二重消費も同時に解消。スコープを `AppDelegate.swift` 1ファイルに限定し、
  `StreamingTranscriber`・energy 経路・start ロールバック（T-033 領域）に手を出していない。
- **スコープ外（意図どおり残置）**:
  - 既存 engine の早期 nil 化（`whisperEngine = nil` をロード前に実施）→ DL 失敗時に前モデルも使えなくなる
    レビュー Low 指摘は本タスク対象外。**ロード成功後差し替え**は別途検討（T-032 受け入れ条件に含めず）。
  - マイク権限要求の fire-and-forget Task も別 Low 指摘で対象外。

## 指摘 / 残課題

- ブロッカーなし。
- フォローアップ候補（別タスク化推奨、本 PR では対応不要）:
  - ロード失敗時に旧 engine を維持して録音継続できるようにする（早期 nil 化の解消）。
  - 並行性の自動テスト（`prewarmWhisper` のロード処理を注入可能にして世代反映を検証）。

## 判定

**承認**。マージ可。実機での「再試行連打／モデル連続切替で `.ready` が正しいモデルを指す」確認を
人間承認時に併せて推奨。
