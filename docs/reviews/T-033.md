# レビュー: T-033 オーディオ↔actor のデータ競合解消＋energy 経路を actor 外へ

- 対象 PR: #15（予定・**マージ保留**／実機確認後に人間が手動マージ）
- 実装: Codex / レビュー: Claude
- 起点: `docs/reviews/code-review-2026-06-10.md`（Top3・高リスク）

## 実装の要点（4ファイル）

1. **設定スナップショット**（`Settings.swift` / `AppDelegate.swift`）
   - `WhisperRuntimeSettingsSnapshot: Sendable`（modelName/language/noSpeechThreshold）を追加。
   - `makeWhisperRuntimeSettingsSnapshot()` を `@MainActor` で提供。`startRecording` が録音開始前に
     MainActor で固め、`start(runtimeSettings:)` に値渡し。
   - `StreamingTranscriber` 内の `Settings.shared` 直接参照を**全廃**。

2. **ミラーバッファでデータ競合を解消**（`StreamingTranscriber.swift`）
   - `LiveAudioBuffer`（`NSLock` 全面保護の `ContiguousArray<Float>`、`@unchecked Sendable`）を導入。
   - タップコールバック（オーディオスレッド）は到着 PCM を mirror へ append。actor 側 transcribe は
     `AudioProcessor.audioSamples`/`purgeAudioSamples` に**一切触らず** mirror の `snapshot`/`count`/
     `purgeKeepingLast` だけを使う。append と read/purge を同一ロックで直列化 → 真のデータ競合を排除。
   - 前提をコード内コメントで明文化。

3. **energy 経路を actor から外す**（`StreamingTranscriber.swift` / `AppState.swift`）
   - `CoalescedEnergyUpdater`（`@unchecked Sendable`）で latest-only coalesce。コールバックから
     `submit` → MainActor で1本だけスケジュールした `drain` → `AppState.applyLiveEnergy`。
   - 非構造化 Task の乱立と順序逆転（波形巻き戻り）を解消。3段ホップ（Task→actor→MainActor）を撤廃。
   - energy は同一オーディオスレッドで `relativeEnergy` を読むため same-thread 安全。

4. **start() のロールバック**（新バッファの activate/deactivate に伴い必要）
   - `startRecordingLive` 失敗時に `runtimeSettings=nil`/buffer deactivate/`stopRecording()` してから throw。
   - `isRunning`/`pipe` はタップ起動成功後に設定。

## 設計評価

- **良い点**: 「波形=入力モニタ、推論非依存」設計を**強化**する方向（コールバック直駆動＋coalesce）。
  WhisperKit の内部スレッド安全性に依存せず、自前ロックバッファで競合を構造的に断つのは堅実。
  スコープを指定4ファイルに限定。
- **無損失スライドの保全**: `slideWindowIfNeeded` の purge を mirror に置換する際、「現在の」バッファ長
  （`liveAudioBuffer.count()`）基準で keep を計算し、transcribe 中に増えた未処理音声を削らない既存原理を
  維持（`StreamingTranscriber.swift:384-391`）。✅

## ⚠️ 要注意点 / フォローアップ候補

1. **`AudioProcessor.audioSamples` の非有界成長（メモリ退行の可能性）**
   - actor 側が `purgeAudioSamples` を呼ばなくなったため、WhisperKit 内部の `audioSamples` は録音セッション
     中ずっと増え続ける（約 16k floats/s ≒ 3.8MB/分）。短時間ディクテーションでは問題ないが、長時間録音で
     メモリが増加する。
   - 候補対策（別タスク化推奨）: コールバックは `processBuffer` と同一スレッドのため、**コールバック内で
     `audioProcessor.purgeAudioSamples` を呼べば same-thread で安全**に内部バッファも頭打ちにできる可能性。
     要 WhisperKit 仕様確認。
2. **実機確認が品質ゲート**: 本変更はコア並行性の再設計。`xcodebuild test`（13 tests）は通るが、
   「波形が固まらない/巻き戻らない」「テキスト消失なし」は実マイク＋実機でしか担保できない。
   → 本 PR は**マージ保留**。下記チェックリストを人間が確認後にマージ。
