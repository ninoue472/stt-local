# 仕様: 推論ステータスの可視化 ＋ 波形の入力追従

## 背景・課題
リアルタイム文字起こしで、ユーザーに**いま何が起きているか**が伝わっていない。

1. **波形が入力に反応しないことがある。** 喋っていても波形が固まる瞬間がある。
   → 「マイクが拾えているのか」がわからず、確信を持って喋れない。
2. **推論の進行状況が伝わらない。** 遅いこと自体ではなく、状況不明が問題。
   - 内部には committed / confirmed / unconfirmed の 3 層があるのに、UI では 1 本の
     文字列に潰れており、**確定/未確定の区別が見えない**。
   - 「推論中」を示すシグナルが存在しない（Phase は recording/processing のみ）。

## 用語
- **確定 (confirmed)**: 再デコード対象から外れ、もう変化しないテキスト
  （`committedText` + `confirmedSegments`）。
- **未確定 (unconfirmed)**: 現在ウィンドウ末尾の、次の推論で変わりうるテキスト
  （`unconfirmedSegments`）。
- **推論中 (inferring)**: `pipe.transcribe(...)` が今まさに 1 パス実行されている状態。

## UX 決定（ユーザー承認済み）
- 波形: **現状の横スクロール波形を維持**し、推論中の固まりを解消＋感度を上げる。
- 確定/未確定の見分け: **未確定はグレー薄色**、確定は通常色。
- 推論ステータス: **テキストバッジ「● 推論中…」＋ 推論中だけドット（アイコン）が脈動**。

---

## 機能 A: 推論ステータスの可視化

### A-1. 確定/未確定のテキスト色分け
- 録音中・処理中、確定テキストは通常色、未確定テキスト（末尾）はグレー薄色で表示する。
- 未確定テキストの末尾には進行を示す `…`（または点滅カーソル相当）を付ける。
- あるテキストが未確定→確定へ昇格すると、色が薄→濃へ切り替わる。

#### 受け入れ条件
- [ ] 録音中、`unconfirmedSegments` 由来の末尾テキストがグレー薄色で表示される。
- [ ] `committedText` + `confirmedSegments` 由来のテキストが通常色で表示される。
- [ ] 未確定だった語が確定に昇格すると、表示色が薄→濃へ変わる。
- [ ] `.ready`（確定後）は `lastFinalText` が全文通常色で表示される。
- [ ] コピー内容（確定+未確定の連結）は従来と完全に一致し、変わらない。

### A-2. 推論ステータスバッジ
- パネルに小さなステータスバッジを表示する（波形の近傍）。
- `transcribe()` 実行中はドットが脈動し「推論中…」を示す。
- `transcribe()` 非実行（次の新規音声を待っている）録音中は脈動を止め、待機を示す
  （例「聞いています」）。
- 録音停止後の最終パス（`.processing`）でも「推論中…」（脈動）を示す。

#### 受け入れ条件
- [ ] `transcribe()` 実行中、バッジが「推論中…」になりドットが脈動する。
- [ ] `transcribe()` 非実行の録音中はドットの脈動が止まり、待機ラベルになる。
- [ ] `.processing` 中もバッジが「推論中…」（脈動）になる。
- [ ] `.ready` ではバッジが消える（または「確定」相当の静的表示）。
- [ ] バッジの状態は実際の `transcribe()` 開始/終了に同期する（飾りのアニメではない）。

---

## 機能 B: 波形が入力に追従（推論中も固まらない）

### 要件
- 録音中、発話中（= `transcribe()` 実行中を含む）も波形が滑らかに動き続ける。
- 通常の発話音量で明確にバーが立つ感度。無音ではベースラインへ静まる。

### 受け入れ条件
- [ ] `transcribe()` 実行中も波形が更新され続け、1 秒以上固まらない。
- [ ] 通常会話の音量でバーが領域高さの大半まで立つ（感度十分）。
- [ ] 無音時はバーがベースラインへ静まり、発話で立つ（入力に追従）。
- [ ] 文字起こしの精度・速度・最終テキストは不変（**タイミング中立**）。

---

## 非対象（今回スコープ外）
- 波形方式の変更（Siri 風 / レベルメーター化）。現状維持。
- デコード閾値（temperatureFallbackCount 等）の見直し。
- 確定/未確定の境界ロジック自体（`requiredSegmentsForConfirmation`）の変更。
